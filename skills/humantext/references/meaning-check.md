# 뜻이 바뀌었는지 보는 기준

다시 쓴 글이 아래 여섯 가지에서 원문과 같아야 한다. 하나라도 다르면 그 문장은 실패다.
이 기준은 yomiyasu(nanaism/yomiyasu, MIT)의 「言い直しテスト」를 한국어에 맞게 옮겼다.

## 1. 여섯 가지

| 항목 | 같다고 볼 때 | 바뀐 예 |
|---|---|---|
| 무엇에 대한 말인가 | 주제와 논점이 같다 | 이 설계의 핵심은 단순함이다 → 이 설계의 목표는 단순함이다 |
| 무엇을 인정하고 부정하나 | 부정이 사라지거나 생기지 않았다 | 새 절차로 재작업이 없어진 것은 아니다 → 새 절차로 재작업이 없어졌다 |
| 누가 누구에게 하나 | 행위자와 상대가 같다 | 김 팀장이 박 대리에게 확인을 부탁했다 → 김 팀장이 확인했다 |
| 범위와 조건 | "일부", "~인 경우에만", "~까지"가 같은 곳에 걸린다 | 관리자만 지울 수 있다 → 지울 수 있다 |
| 단정·추정·전언의 세기 | 단정, 추정, 전해 들은 말이 그대로다 | 설정 오류로 보인다 → 설정 오류다 |
| 숫자·이름·시기 | 수, 단위, 이름, 날짜가 같다 | 약 30건 → 30건 |

## 2. 판단 순서

1. 고친 문장 하나를 쓴다.
2. 여섯 가지를 원문과 비교한다.
3. 하나라도 다르면 고친 문장을 버리고 다시 쓴다. 두 번 해도 안 되면 원문 표현을 남기고 「확인할 것」에 적는다.
4. 문장을 지울 때는 그 문장에만 있는 주장, 조건, 숫자, 기한이 없는지 본다. 있으면 다른 문장으로 옮긴다.

## 3. 남겨야 하는 부정

"A가 아니라 B"를 B만으로 바꾸면 주장이 바뀌는 경우가 있다. 아래는 남긴다.

| 원문 | 남기는 이유 |
|---|---|
| 느린 원인은 데이터베이스가 아니라 사내 네트워크였다 | 독자가 의심할 만한 원인을 바로잡는다 |
| 처음엔 메모리 부족을 의심했지만 실제로는 파일 개수 제한이었다 | 검증에서 틀린 가설과 실제 원인을 나란히 둔다 |
| 이 표의 숫자는 매출이 아니라 주문 건수다 | 잘못 읽기 쉬운 숫자의 뜻을 바로잡는다 |
| 탓하려는 게 아니라 경위를 알고 싶을 뿐입니다 | 상대가 받아들일 방식을 먼저 바로잡는다 |

판단이 안 서면 남긴다.

## 4. 면책 문장과 유보의 차이

- **면책 문장**: 독자가 묻지 않은 반론을 미리 막는 문장. "이것이 정답이라고 보지는 않는다." 지운다.
- **유보**: 실제로 확인 안 된 사실. "표본이 87편이라 모델 간 차이는 오차 안에 있다." 남긴다. 다만 한 곳에 모아 한 번만 쓴다.
